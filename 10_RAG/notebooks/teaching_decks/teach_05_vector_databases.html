03 / 17
The fix

Approximate Nearest Neighbor, ANN for short

Instead of checking every vector, build a shortcut structure that finds the closest ones almost every time, in a fraction of the time. That's the entire idea behind every vector database.
Read every book
exact search, always correct, painfully slow at scale
Use the index
ANN search, almost always correct, fast
For the trainer

Library analogy works well here. Nobody reads every book to find one topic, they use the index card system. That index is a little imperfect but nobody cares because it's fast and right almost every time. FAISS, HNSW, and IVF are all just different ways of building that index.

05 / 17
FAISS, tool one

HNSW, walking a map instead of scanning a list

HNSW builds a layered graph of connections between vectors. A search starts at the sparse top layer, takes a few long jumps, then drops into denser layers to home in on the answer, touching only a handful of vectors along the way.
Example question: "What's the refund window if I cancel my subscription?"
path actually walked nodes never touched the answer
Why does it always start at node 1?

It's not chosen based on the question. One entry point gets fixed the moment the index is built, usually just whichever vector was added first. Every single search, no matter what's being asked, starts at that exact same node and greedily works outward from there.

Walking through the example above
  1. Start at node 1, the fixed entry point. Every question lands here first, including this one.
  2. Compare the question to node 1's neighbors. Node 2 is closer to "refund window," so jump there.
  3. No neighbor beats node 2 at this layer, so drop down and land on node 3, the closest match.
For the trainer

Read the three numbered steps out loud against the graph before saying anything else. Then ask the room the question they're probably already thinking: why node 1, why not somewhere closer to begin with. The answer is the callout, it's fixed at build time, the algorithm never picks a custom starting point per question.

FAISS, tool two

IVF, sort into neighborhoods first, then only visit the closest ones

Before any question ever arrives, IVF groups every vector into clusters. When a question comes in, it only searches inside the nearest couple of clusters and ignores the rest completely.
incoming question
searched, the question gets compared to these skipped, nothing inside gets touched at all the incoming question
For the trainer

Follow the two dashed lines from the question down to the two orange clusters, those are the only neighborhoods that get searched. The three gray circles off to the side are skipped completely, not one vector inside them gets compared. That's nprobe, literally how many of these circles you bother checking.

Pinecone, in practice

The engine, plus somebody else running it for you

Same underlying idea again. Pinecone owns the infrastructure, scales automatically, and adds namespaces so one index can hold cleanly separated partitions.
query "how do I get my money back", filtered to billing top match score 0.357
For the trainer

Be honest about the trade here. Zero ops sounds free, it isn't, you're paying in dollars and in being locked into their platform instead of paying in engineering time. Frame it as a real decision, not a strictly better option.

Questions to expect

What students usually ask here

Is Chroma just a worse version of Pinecone then?
No, it's a different trade, not a worse one. Chroma means you run it yourself with no ongoing cost beyond your own server. Pinecone means someone else runs it and you pay them instead. Neither is strictly better, they fit different situations.
Why not just always use exact search if my dataset is small?
You can, and FAISS's flat index is exactly that. The moment your corpus grows into the millions, exact search stops being practical, so many teams pick an ANN index from the start even at small scale, just to avoid a rewrite later.
Do I need to understand HNSW internals to use a vector database?
Not to use one, but you'll hit a wall the first time recall looks wrong and you don't know which knob to turn. Today's session is exactly that knob.
