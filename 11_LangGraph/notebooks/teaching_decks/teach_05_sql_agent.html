Step 2 · the toolbox

Four tools, one job each

sql_db_list_tables
Returns the table names. Nothing else.
Stops the agent from inventing "songs".
sql_db_schema
Columns, types, and three sample rows per table.
The sample rows are why it gets JOINs right.
check_query (a node, not a tool)
An LLM reviews the SQL, then calls the runner itself.
Structure, not a prompt. It cannot be skipped.
sql_db_query
Actually executes it and returns rows.
The only tool that touches the database.
⚠️ In production the whole toolbox runs as a read-only database user. Never grant INSERT, UPDATE or DELETE.

Step 6 · production

  
Six controls before this touches real data


  

    

      
      
Read-only DB user
Blocks DROP and DELETE even if the model hallucinates one.

    

    

      
      
Table allow-list
The agent sees sales_*. It never learns payroll exists.

    

    

      
      
Row LIMIT, twice
In the prompt and in a validator. Stops full-table scans.

    

    

      
      
SELECT-only allow-list
Reject anything matching INSERT, UPDATE or DELETE.

    

    

      
      
interrupt() before run
